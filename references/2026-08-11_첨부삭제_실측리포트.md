2. **카톡 앱을 종료하면 안 된다.**
   R2 실측(§6): 앱을 quit 하고 재실행하니 ① **「다른 기기에서 로그인 중」 강제 로그아웃 게이트**가 떠서 무인 복구 실패, ② 복구 후 **그날 이 방에서 보낸 대화 내역이 이 맥 클라이언트에서 통째로 사라졌다**(상대 단말에는 남아 있음). 즉 **종료 = 로컬 이력 소실 + 사람 개입 필요**.

### 경로 D 가 불가한 근거 (실측)

```bash
$ osascript -e 'tell application "KakaoTalk" to get properties'
execution error: KakaoTalk에 오류 발생: AppleEvent 시간이 초과되었습니다. (-1712)
$ ls /Applications/KakaoTalk.app/Contents/Resources/*.sdef      # → 없음
$ plutil -extract NSAppleScriptEnabled  ... Info.plist          # → 키 없음
$ plutil -extract OSAScriptingDefinition ... Info.plist         # → 키 없음
```
→ KakaoTalk 은 **AppleScript 사전이 없다.** 쓸 수 있는 건 System Events 를 통한 **UI 스크립팅**뿐이다.
AX API 로 입력창에 넣을 수 있는 것도 **텍스트(AXValue)** 뿐이고, 파일을 요소에 직접 꽂는 속성은 없다.
다만 **AX 로 «메뉴 항목을 누르는 것»은 된다** → 이걸 이용해 A-2(전역 ⌘V 대신 편집>Paste 메뉴 Press)를 만들었다.

pb = NSPasteboard.generalPasteboard(); pb.clearContents()
pb.writeObjects_([NSURL.fileURLWithPath_("/abs/path/문서.pdf")])
# 생성되는 타입(실측): public.file-url, NSFilenamesPboardType, Apple URL pasteboard type ...

# 2) 대상 창을 «메뉴 항목»으로 확정 선택 — 「창」 메뉴의 정확 제목 항목 Press

select_room("신현빈")

# 3) 🔴 붙여넣기 직전 가드: 최전면앱 == KakaoTalk  AND  app.AXFocusedWindow.AXTitle == "신현빈"

#       → 예외를 삼키고 «시트가 사라졌는지»로 성공을 판정할 것

## 5. 「보낸 메시지 삭제」 실측

### 5.1 컨텍스트 메뉴가 AX 에 안 잡힌다 (핵심 함정)

우클릭 메뉴는 **접근성 트리에 노출되지 않는다.** `app.AXChildren` 에 `AXMenu` 가 생기지 않고, 창의 자식에도 없다.
→ 해결: **CGWindowList 로 «레이어 101 짜리 팝업 창»을 찾고, 그 영역을 캡처해 Vision OCR 로 항목 좌표를 얻는다.**

```python
# 1) 메뉴 창 찾기 — 오너명이 시스템 언어 따라 '카카오톡' 또는 'KakaoTalk' 인 점 주의
info = Quartz.CGWindowListCopyWindowInfo(OnScreenOnly|ExcludeDesktopElements, kCGNullWindowID)
menu = [w for w in info if w['kCGWindowOwnerName'] in ('KakaoTalk','카카오톡')
        and w['kCGWindowLayer'] >= 1][0]      # 실측: layer=101, 예: 111x296 @(914,691)
# 2) 그 영역 캡처 → VNRecognizeTextRequest(languages=['ko-KR','en-US'])
# 3) 원하는 라벨의 중심 좌표를 클릭
```
⚠️ 메뉴 위치는 **커서 위치 그대로가 아니다.** 화면 아래로 넘칠 것 같으면 macOS 가 위로 밀어 올린다(실측: 클릭 y=738 → 메뉴 top y=691). **좌표를 상수로 박으면 안 된다.**

### 5.2 메뉴 구성 (실측 OCR 원문)

| 메시지 종류 | 메뉴 항목 |
|---|---|
| 내 텍스트 | 오려두기 / 복사하기 / 붙여넣기 / 대화 캡처 / **모두에게서 삭제** / **나에게서만 삭제** / 수정 / 답장 / 공감 / 공유 / 공지 |
| 내 파일 | 열기 / 대화 캡처 / **모두에게서 삭제** / **나에게서만 삭제** / 답장 / 공감 / 공유 / 공지 |
| 내 사진·영상 | 폴더열기 / 대화 캡처 / **모두에게서 삭제** / **나에게서만 삭제** / 답장 / 공감 / 공유 / 공지 |

→ 파일·미디어에는 **「수정」이 없다.** 텍스트에만 있다.

### 5.3 두 삭제의 차이 (실측)

| | 모두에게서 삭제 | 나에게서만 삭제 |
|---|---|---|
| 절차 | 메뉴 클릭 → **끝** (확인창 없음) | 메뉴 클릭 → **다중선택 모드** → 체크박스 → **확인** → 확인시트 **삭제** |

### R7 미검증 사유 (추측으로 메우지 않음)

화면을 잠그면 해제에 **사용자 암호**가 필요하고 나는 그것을 갖고 있지 않다. 잠긴 세션에서는 GUI 자동화가 진행되지 않으므로, 시도하면 **작업 전체가 사람 개입 없이는 복구 불가 상태로 멈춘다.** 위험 대비 이득이 없어 **의도적으로 실행하지 않았다.**
다만 이론적으로 확실한 것: **잠금 화면 동안에는 대상 앱이 키 윈도우를 가질 수 없어 이 프로토콜의 가드가 전부 실패하고 «아무것도 전송하지 않고 정지»한다.** (= 잘못 보내지는 않는다) 잠금 해제 «직후» 동작 여부는 미검증.

## 7. ★포커스 강탈 — 사고 재현과 방어 검증

### T1. 사고 재현 (카톡 밖에서 안전하게 증명)

기존 `kakao_send.py` 와 동일한 «pbcopy → 전역 ⌘V → 전역 Enter» 시퀀스를, TextEdit 를 최전면에 둔 채 실행.

```json
{"frontmost_when_typed": "TextEdit",
 "landed_in_textedit": true,
 "textedit_file_text": "[유출테스트] 이 문자열이 카톡 밖에서 발견되면 키입력이 샌 것이다\n"}
```
→ **전역 키입력은 그 순간 최전면 앱으로 간다.** 이게 오발송의 물리적 원인이다.
카톡이 최전면이되 **다른 방**이 키 윈도우면, 같은 원리로 그 방에 찍히고 Enter 까지 먹는다.

### T2~T4. 방어가 실제로 막아내는가 (실제 발신 없이 정지하는지 확인)

| 테스트 | 깨뜨린 방법 | 결과 | 정지 메시지 | 롤백 |
|---|---|:--:|---|:--:|
| T2 | 전송 지점을 **터미널 창으로 덮고** 최전면 강탈 | ✅ 차단 | `[STOP:before-send-click] 최전면 앱이 'Terminal' — 키 입력 유출 위험` | ✅ |
| T3 | 창은 안 덮고 **최전면만** 강탈 | ✅ 차단 | 동일 | ✅ |
| T4 | ★**카톡 «메인 목록창»이 클릭 지점을 덮음** | ✅ 차단 | `[STOP:before-send-click] 카톡 focused window 가 '카카오톡' — '신현빈' 아님` | ✅ |
| T5 | 방해 제거 후 정상 전송 | ✅ 전송 | – | – |

- 세 케이스 모두 **방 row 수 변화 0** (18 → 18) = **아무것도 전송되지 않았다.**
- T2/T3 은 롤백으로 입력창을 비워 **초안 잔여물도 남기지 않았다.**
- ★**T4 가 핵심이다.** «카톡이 최전면인가?»만 보는 검사로는 절대 못 잡는다. 같은 앱의 다른 창이 덮은 상황이라 프론트앱 검사는 통과한다. **`app.AXFocusedWindow.AXTitle` 을 함께 봐야** 잡힌다.
- 클릭 지점 판정에는 **AX 히트테스트**(`AXUIElementCopyElementAtPosition`)를 쓴다. CGWindowList 만 보면 «스크린샷» 같은 **클릭 통과 오버레이**(layer 24, 전체화면)를 덮개로 오인해 오탐이 난다(실측으로 겪음).

### (c) 사람이 마우스를 움직이거나 클릭하면 — 잔존 위험

- 텍스트 본문·파일 경로는 **키보드/마우스를 거치지 않는다**(AXValue, 클립보드+메뉴). 사람이 마우스를 움직여도 **내용이 다른 곳에 찍히는 일은 없다.**
- 남는 위험은 **마지막 «전송 버튼 클릭» 한 번**뿐이다. 가드 통과 후 클릭까지 간격이 ~50ms 이고, 그 사이에 사람이 창을 바꾸면 클릭이 빗나갈 수 있다. 결과는 «전송 안 됨»이며 **다른 방으로 가지는 않는다**(클릭 지점은 대상 창 내부 좌표라 다른 방의 전송 버튼이 그 자리에 올 수 없다 — 온다면 히트테스트가 그 창 제목을 반환해 정지).
- 파일 첨부는 여기서 한 겹 더 안전하다: **확인 시트가 대상 창의 자식으로 떠야만** 전송으로 넘어가므로, 붙여넣기가 샜다면 시트가 안 뜨고 **아무것도 보내지지 않은 채 정지**한다.

### (d) 알림 팝업 / 화면보호기

- 알림 배너·스크린샷 오버레이 같은 **상위 레이어 창**은 클릭 지점 판정에서 오탐을 만든다 → AX 히트테스트 1차 + 일반 레이어(layer≤0) 창 2차 로 이중 확인하도록 했다(§7 T2 에서 실제로 스크린샷 오버레이 오탐을 겪고 고침).
- 화면보호기/잠금은 R7 과 동일 사유로 미검증.

## 9. 속도 — 실측과 개선

**측정 방법**: 같은 PDF(92.1KB)를 3건 연속 전송, 단계별 타이머. **검증(도착 재조회 + 타 방 오염검사 + 활성방 확인)은 전 구간 유지.**

| 단계 | 개선 전 | 1차 개선 | **최종** |
|---|--:|--:|--:|
| ensure(창 복구) | 2.71 | 0(배치 1회) | **0**(배치 1회) |
| 전 스냅샷 + 목록 스냅샷 | 6.19 | 4.99 | **3.68** |
| 붙여넣기 | 3.10 | 2.47 | **2.60** |
| 확인 시트 등장 | 0.46 | 0.42 | **0.38** |
| 전송 확정 | 2.47 | 0.52 | **0.53** |
| 도착 대기 | 6.50 | 0.24 | **0.20** |
| 검증(재조회+오염검사) | 6.34 | 4.91 | **3.79** |
| **1건 합계** | **27.8초** | 13.6초 | **12.2초** (단독 실행 시 13.1초) |

**개선 내용 (검증은 하나도 줄이지 않음)**
1. **전체 row 깊이 순회 → «개수 + 마지막 4개»만** (`snapshot_light`). 방에 메시지가 쌓일수록 효과가 커진다.
2. **고정 sleep → 조건 폴링.** `time.sleep(2.5)` 로 기다리던 확인 시트·도착을 «시트가 떴나/사라졌나», «row 가 늘었나»로 폴링(0.15~0.2s 간격). 도착 대기 6.5초 → 0.2초.
3. **AX 요소 캐싱.** 검색 필드·채팅목록 테이블을 매번 트리 전체에서 찾던 것을 캐시. (캐시 무효화 시 자동 재탐색)
4. **채팅목록은 상위 10개만.** 오발송이 나면 그 방이 목록 «맨 위»로 올라오므로 전수 조회가 불필요.
5. **여러 건은 `ensure_room` 1회로 묶기.** 건별 가드·검증은 그대로 유지.

**한 것 중 «개선이 아니어서 되돌린 것»**: 메인 목록창이 닫혀 있을 때 오염검사가 조용히 건너뛰어지며 1건 3.95초가 나왔다. 이건 빨라진 게 아니라 **검증이 사라진 것**이라, 오염검사 불가를 **하드 실패**로 바꾸고 목록창을 자동 복구하도록 고쳤다(그래서 13.1초).

## 10. ⚠️ 함정 목록

1. ⚠️ **앱을 종료하지 마라.** 재실행 시 「다른 기기에서 로그인 중」 게이트 + **그날 보낸 로컬 이력 소실**(§6 R2).
2. ⚠️ **전역 키스트로크(⌘V/Enter)를 쓰지 마라.** 최전면 앱으로 샌다(§7 T1 실측 증거).
3. ⚠️ **«카톡이 최전면인가»만 확인하면 안 된다.** 같은 앱의 다른 창이 키 윈도우일 수 있다 → `AXFocusedWindow.AXTitle` 병행 확인(§7 T4).
4. ⚠️ **카톡 커스텀 버튼은 `AXPress` 가 `AXErrorFailure` 를 던지면서 «동작한다».** 예외로 실패 판정하면 안 되고, **결과(시트 소멸/row 증가)로 판정**해야 한다.
5. ⚠️ **전송 버튼은 `AXPress` 를 무시한다.** 입력창 `AXValue` 는 먹지만 전송 버튼은 좌표 클릭이 필요하다 → 클릭 전 **AX 히트테스트**로 수신자 확인 필수.
6. ⚠️ **우클릭 컨텍스트 메뉴는 AX 에 없다.** CGWindowList(layer≥1) + Vision OCR 로 처리. 메뉴 위치는 화면 경계에 따라 **위로 밀린다** — 좌표 상수 금지.
7. ⚠️ **CGWindow 오너명은 `카카오톡`**(한글) 이다. `KakaoTalk` 만 찾으면 아무것도 못 찾는다.
8. ⚠️ **클릭 통과 오버레이(스크린샷·알림, layer>0)를 «덮개»로 오인**하지 마라. AX 히트테스트를 1차 판정으로.
9. ⚠️ **타 방 오염검사에 «변했다»만 쓰면 못 쓴다.** 실계정은 수신 메시지가 계속 들어와 오탐이 난다. **다른 방 미리보기에 «우리가 보낸 내용»이 보이는가**로 판정해야 한다.
10. ⚠️ **채팅 검색 필터가 남아 있으면 목록이 잘려** «방이 사라졌다/생겼다» 오탐이 난다 → 스냅샷 전 필터 해제(실측으로 R1 이 이 오탐으로 실패 판정됨).
11. ⚠️ **PNG 는 파일이 아니라 사진**이 된다. 파일명 유지가 필요하면 쓸 수 없다.
12. ⚠️ **첨부 파일에 「유효기간 ~2주」**가 붙는다. 거래처가 늦게 받으면 만료된다.
13. ⚠️ **이미지 2장 이상이면 「묶어보내기」 안내 시트**가 먼저 뜬다. 처리 안 하면 중복/미발송 혼란.
14. ⚠️ **「나에게서만 삭제」는 회수가 아니다.** 상대·다른 기기엔 그대로 남는다.
15. ⚠️ **화면 밖·스크롤 밖 메시지는 우클릭 불가.** 특히 마지막 메시지는 입력창에 가려 스캔 밴드를 벗어난다.
16. ⚠️ **`open -a KakaoTalk` 는 이미 실행중인 앱의 «닫힌 목록창»을 되살리지 못한다** → 「창 > 채팅」 메뉴 항목 Press 사용.
17. ⚠️ **Finder AppleScript(`select`)는 -1712 로 자주 죽는다.** Finder 를 경유하지 않는 NSPasteboard 방식을 쓸 것.
