# 카카오톡 안전 전송 프로토콜 (텍스트 · 파일 공용)

> 2026-08-11 실측 기반. 구현체: `~/.claude/skills/kakao_manager/scripts/safe_send/`
> **이 문서는 kakao_manager 의 모든 전송에 적용되는 «필수 전제»다.** 텍스트 전송도 예외가 아니다 — 오히려 텍스트가 더 위험하다.

---

## 0. 왜 필요한가 (실측으로 증명된 사고 메커니즘)

기존 `kakao_send.py` 는 이렇게 보낸다:

```python
subprocess.run(["pbcopy"], input=text)   # 클립보드에 본문
key_code(9, "command down")              # 전역 ⌘V
key_code(36)                             # 전역 Enter
```

**전역 키입력은 «그 순간 최전면 앱의 키 윈도우»로 간다.** 카톡을 activate 한 뒤라도, 그 사이에 다른 앱이 올라오거나 카톡의 다른 창이 활성화되면 그대로 샌다.

실측 증거 (T1, 카톡 밖에서 안전하게 재현):

```json
{"frontmost_when_typed": "TextEdit",
 "landed_in_textedit": true,
 "textedit_file_text": "[유출테스트] 이 문자열이 카톡 밖에서 발견되면 키입력이 샌 것이다\n"}
```

같은 원리로 **카톡의 다른 대화방이 활성이면 그 방에 본문이 찍히고 Enter 까지 먹는다.**
파일은 붙여넣기 후 «확인 시트»라는 관문이 있어 그나마 한 번 걸리지만, **텍스트는 관문이 없다. 찍히는 순간 끝이다.**

## 1. 6대 원칙

### (1) 전송 전 — 카톡 강제 활성화 + 대상 방 «명시적» 선택 + 제목 확인

```python
ensure_room("신현빈")        # 앱 실행 / 로그인 / 창 확보 / 최소화 해제 / 화면 안으로 / 활성화
select_room("신현빈")        # 「창」 메뉴의 «정확 제목» 항목을 객체로 Press
```

- **「창」 메뉴 항목 Press 를 쓴다.** 좌표 클릭이나 검색이 아니라 «제목이 정확히 일치하는 메뉴 항목 객체»를 누르므로 다른 방이 선택될 여지가 구조적으로 없다.
- 방 창이 없어 검색으로 열어야 하면, 연 뒤 **«새로 열린 방이 대상 하나뿐인지»** 검증한다. 두 개 이상 열렸거나 다른 이름이 열리면 **즉시 정지**.
- 창이 화면 밖으로 걸쳐 있으면 `NSScreen.visibleFrame` 로 **전체가 보이도록 위치·크기를 보정**한 뒤에만 진행한다.

### (2) ★가장 중요 — 전송 유발 동작 «직전» 재확인

```python
def guard(title, step, require_front=True):
    w = find_room(title)
    if w is None:                     raise Abort(f"[STOP:{step}] 창이 사라짐")
    if focused_window_title() != title:
        raise Abort(f"[STOP:{step}] 카톡 focused window 가 다름 — 전송 중단")
    if require_front and frontmost_app() != "KakaoTalk":
        raise Abort(f"[STOP:{step}] 최전면 앱이 다름 — 키 입력 유출 위험")
```

두 가지를 **함께** 본다:

| 확인 항목 | 무엇을 막나 |
|---|---|
| `frontmost_app() == "KakaoTalk"` | 다른 «앱»으로 새는 것 |
| `app.AXFocusedWindow.AXTitle == 대상방` | 같은 앱의 «다른 창»으로 가는 것 |

★**둘 중 하나만으로는 부족하다.** 카톡 메인 목록창이 활성이면 프론트앱 검사는 통과하지만 키 입력은 목록창으로 간다. 실측 T4 에서 이 케이스가 두 번째 검사에만 걸렸다.

**확인과 실행 사이 간격을 최소화한다.** 가드 → (다른 코드 없음) → 실행. 가드 뒤에 로그 출력·스냅샷 같은 걸 끼워넣지 않는다.

### (3) 전송 후 — 3중 검증

```python
① 보낸 방 재조회      : row 수가 늘었는가 + 본문/파일명이 실제로 보이는가
② ★타 방 오염 검사    : 다른 방 미리보기에 «우리가 보낸 내용»이 나타났는가
③ 활성 방 동일성      : 전송 직후 focused window 가 여전히 대상 방인가
```

**②의 판정 기준이 중요하다.** «다른 방이 변했다»만으로 정지하면 실계정에서는 못 쓴다 — 수신 메시지가 계속 들어와 매번 오탐이 난다. 그래서 2단계로 나눈다:

- **HARD(오발송 확정)**: 다른 방의 마지막 메시지 미리보기에 **우리 payload(파일명/본문 앞부분)** 가 보임 → **즉시 전체 정지**
- **SOFT(경고)**: 다른 방이 변했지만 payload 와 무관 → 상대의 수신으로 보고 기록만 남김

⚠️ 채팅 **검색 필터가 걸려 있으면 목록이 잘려** «방이 사라졌다/생겼다» 오탐이 난다 → 스냅샷 전 필터를 반드시 해제한다.
⚠️ 메인 목록창이 닫혀 있으면 ②를 아예 못 한다 → **«검사 불가»를 성공으로 넘기지 말고 하드 실패**로 처리하고, 목록창을 「창 > 채팅」 메뉴로 복구한다.

### (4) 불일치 시 — 즉시 전체 정지, ★자동 재시도 금지

- 모든 가드 실패는 `SystemExit("[STOP:...]")` 로 **프로세스를 끝낸다.** 예외를 잡아 다음 단계로 넘어가지 않는다.
- **재시도 루프를 넣지 않는다.** 재시도는 오발송을 두 배로 만든다. 사람이 원인을 확인한 뒤 다시 실행한다.
- 정지 시 **롤백**한다:
  - 텍스트: 입력창에 넣어둔 본문을 `AXValue=""` 로 회수 (초안 잔여물 금지)
  - 파일: 확인 시트를 **「취소」** 로 닫음 (아무것도 전송 안 됨)

### (5) ★좌표·포커스에 의존하지 않는 경로를 1순위로

| 동작 | 안전한 방법 | 쓰지 말 것 |
|---|---|---|
| 대상 창 선택 | 「창」 메뉴의 정확제목 항목 `Press()` | 좌표 클릭 |
| 본문 입력 | 입력창 요소 `AXValue = text` (**카톡 비활성 상태에서도 동작 확인**) | `pbcopy` + 전역 ⌘V |
| 입력창 포커스 | 요소 `AXFocused = True` | 입력란 좌표 클릭 |
| 파일 붙여넣기 | 「편집 > Paste」 **메뉴 항목** `Press()` (카톡에만 전달) | 전역 ⌘V |
| 파일 선택 패널 | 「파일전송」 버튼 요소 | `⌘O` 전역 단축키 |

**남는 유일한 좌표 동작은 «전송 버튼 클릭» 하나다** (카톡 전송 버튼은 `AXPress` 를 무시한다 — 실측). 그래서 클릭 직전에 한 겹 더 검사한다:

```python
hit = hit_test(x, y)                       # AXUIElementCopyElementAtPosition
if hit["pid"] != kakao_pid():        raise Abort("클릭 수신자가 카톡이 아님")
if hit["window"] not in (None, title): raise Abort("클릭 수신 창이 대상 방이 아님")
top = window_at_point(x, y, normal_only=True)   # layer<=0 만
if top and top["name"] != title:     raise Abort("그 지점을 덮는 창이 있음")
click(x, y)
```

⚠️ **CGWindowList 만 보면 안 된다.** 스크린샷·알림 같은 **클릭 통과 오버레이**(layer>0, 전체화면)를 덮개로 오인해 오탐이 난다. **AX 히트테스트가 1차 판정**이다.

**파일 첨부의 구조적 안전장치**: 붙여넣기가 다른 방으로 샜다면 **대상 창에 확인 시트가 뜨지 않는다.** 시트 존재 자체가 «올바른 방에 들어갔다»는 증거이며, 없으면 아무것도 전송하지 않고 정지한다.

### (6) 실패 시 롤백 — 이미 잘못 나갔다면

| 상황 | 회수 가능? | 방법 |
|---|---|---|
| 잘못된 방으로 전송됨 | ✅ 가능 | 그 방에서 **「모두에게서 삭제」** (우클릭 → 즉시 실행, 확인창 없음) |
| 시간이 꽤 지남 | ✅ **48분 경과까지 성공 확인** | 상한 미측정. 통설의 5분 제한은 관측되지 않음 |
| 「나에게서만 삭제」로 처리 | ❌ **회수 아님** | 내 현재 기기에서만 사라지고 상대·다른 기기엔 남는다 |
| 앱이 종료·재로그인됨 | ❌ 회수 불가 | 로컬 이력이 사라져 클라이언트에서 대상 메시지를 찾을 수 없다 |

⚠️ **롤백을 한다고 다른 방에 «죄송합니다» 같은 걸 자동으로 보내지 마라.** 그건 또 하나의 전송이다. 사람에게 보고하고 지시를 받는다.

## 2. 전송 시퀀스 (그대로 따라 쓸 것)

### 2.1 텍스트

```python
ensure_room(room)                              # ① 창 복구
cl_before = chatlist(); before = snapshot_light(room)

select_room(room)                              # ② 대상 창 확정 선택
inp, btn = room_input(w), send_button(w)

draft = inp.AXValue                            # ③ 사람 초안 보호
if draft and draft.strip():
    raise Abort("입력창에 사람이 쓰던 초안이 있음 — 덮어쓰지 않고 정지")

inp.AXValue = text                             # ④ ★키입력 없이 본문 주입
assert inp.AXValue == text

try:                                           # ⑤ 🔴 클릭 직전 최종 확인 → 즉시 클릭
    guard(room, "before-send-click")
    assert room_input(find_room(room)).AXValue == text
    click_verified(send_button(find_room(room)), room, "send-click")
except SystemExit:
    inp.AXValue = ""                           # 롤백 (★재시도 안 함)
    raise

poll(lambda: text in joined(snapshot_light(room)))   # ⑥ 도착 확인
verify(room, before, cl_before, expect=text)        # ⑦ 3중 검증
```

### 2.2 파일

```python
ensure_room(room)
cl_before = chatlist(); before = snapshot_light(room)

clipboard_files([path])                        # ① 파일 URL 을 클립보드에
select_room(room)                              # ② 대상 창 확정 선택
guard(room, "before-paste")
room_input(w).AXFocused = True                 # ③ 좌표 클릭 없이 포커스
guard(room, "paste")                           # 🔴 붙여넣기 직전 재확인
menu_paste()                                   # ④ 「편집 > Paste」 메뉴 Press

sheet = poll(sheet_ready)                      # ⑤ ★확인 시트가 «대상 창의 자식»으로 떴는가
if not sheet: raise Abort("시트 없음 — 붙여넣기 유출 의심, 아무것도 안 보내고 정지")
assert basename(path) in row_text(sheet)       #    파일명까지 일치 확인

try:    confirm_sheet_fast(room)               # ⑥ 전송 버튼
except: cancel_sheet(room); raise              #    실패 시 «취소»로 롤백

poll(lambda: snapshot_light(room)["count"] > before["count"])   # ⑦ 도착
verify(...)                                                     # ⑧ 3중 검증
```

**이미지 2장 이상**이면 ⑤ 앞에 「묶어보내기」 안내 시트가 먼저 뜬다 → **「확인」**(기본 유지)을 눌러 통과. 「묶어보내기 기능 사용하기」는 사용자 환경설정을 바꾸므로 자동화가 누르지 않는다.

## 3. 방어가 실제로 작동하는지 확인한 기록

| 테스트 | 깨뜨린 방법 | 결과 |
|---|---|---|
| T1 | TextEdit 최전면 + 전역 ⌘V/Enter | **본문이 TextEdit 에 찍힘** — 사고 메커니즘 확정 |
| T2 | 전송 지점을 터미널 창으로 덮고 최전면 강탈 | `[STOP:before-send-click] 최전면 앱이 'Terminal'` — row 18→18, 롤백 완료 |
| T3 | 최전면만 강탈(창은 안 덮음) | 동일하게 정지, row 18→18, 롤백 완료 |
| T4 | ★**카톡 메인 목록창**이 클릭 지점을 덮음 | `[STOP] 카톡 focused window 가 '카카오톡'` — 프론트앱 검사로는 못 잡는 케이스를 잡음 |
| T5 | 방해 제거 후 정상 전송 | ✅ 정상 전송 + 3중 검증 통과 |

**세 방어 테스트 모두 «전송 0건»으로 끝났다.** 막지 못한 케이스는 없었다.

## 4. 잔존 위험 (숨기지 않고 적음)

1. **마지막 클릭 한 번**은 물리 좌표 동작이다. 가드~클릭 간격(~50ms) 사이에 사람이 창을 바꾸면 클릭이 빗나갈 수 있다. 결과는 «전송 안 됨»이지 «다른 방 전송»이 아니다(그 지점의 다른 창은 히트테스트가 잡는다).
2. **타 방 오염검사는 상위 10개 방만** 본다. 오발송이면 그 방이 맨 위로 올라오므로 실용상 충분하지만, 이론적 사각은 있다.
3. **화면 잠금 중에는 검증되지 않았다.** 다만 잠금 상태에서는 가드가 전부 실패해 «아무것도 안 보내고 정지»한다 — 잘못 보내지는 않는다.
4. **앱이 종료되면 프로토콜이 무력하다.** 재로그인 게이트는 사람이 판단해야 하고, 그 시점에 로컬 이력이 소실되어 회수·검증 모두 불가능해진다. → **자동화가 카톡을 종료하는 코드를 넣지 말 것.**

## 5. 체크리스트 (사람이 리뷰할 때)

- [ ] 전송 코드에 `key_code(36)` / `keystroke` / 전역 `⌘V` 가 남아 있지 않은가
- [ ] 전송 직전에 `frontmost_app()` **과** `AXFocusedWindow.AXTitle` 을 **둘 다** 보는가
- [ ] 가드와 실행 사이에 다른 코드가 끼어 있지 않은가
- [ ] 실패 시 **재시도 루프**가 없는가
- [ ] 실패 시 입력창/확인시트 **롤백**이 있는가
- [ ] 타 방 오염검사가 **«우리 payload 가 보이는가»** 로 판정하는가 (단순 «변했다»가 아니라)
- [ ] 오염검사 **불가**를 성공으로 넘기지 않는가
- [ ] 방 이름을 **부분일치**로 찾지 않는가 (정확일치만)
